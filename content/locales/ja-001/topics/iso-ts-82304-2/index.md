# ISO/TS 82304-2

ISO/TS 82304-2は、ISO技術委員会215(ヘルスインフォマティクス)の下で発行された国際技術仕様であり、使いやすさ、技術的堅牢性と信頼性、相互運用性、コンテンツの品質、データのセキュリティとプライバシーにわたって、健康・ウェルネスアプリケーションの品質を評価するための構造化された方法を定義している——完全な医療機器規制の範囲外にありながらも、ユーザーの健康上の決定や行動に重要な影響を与える製品を対象としている。これは特定のギャップを埋めるために存在する:消費者向けの健康・ウェルネスアプリ(フィットネストラッカー、症状日記、ウェルネスコーチングアプリ)の大部分は医療機器として規制されていないが、以前はその基本的な品質と安全性を評価または比較するための共通の構造化された方法が存在しなかった。

## なぜ重要か

アプリストアは、非常に品質にばらつきのある何十万もの健康・ウェルネスアプリをホストしており、共通の技術仕様が存在する前は、患者、臨床医、または医療システムは、星評価やマーケティングの主張を超えて、あるアプリの基本的な品質と安全性を別のものと比較するための構造化された比較可能な方法を持っていなかった——これは、設計の悪い健康アプリが医療機器の規制閾値を満たしていなくても実際の害(不正確なコンテンツ、不十分なデータセキュリティ、誤解を招く主張)を引き起こしうるため重要なギャップである。ISO/TS 82304-2は、非専門家のレビュアーが一貫して評価できるドメインを中心に意図的に構造化されており、これによりいくつかの国家的・商業的な健康アプリ品質ラベリング・キュレーションサービスの技術的基盤となり、医療システムやアプリライブラリに、場当たり的な判断に頼るのではなく、推奨リストにアプリを含めるか除外するかの擁護可能で標準化された方法を提供している。

## 適用方法

```
評価は、単一の数値公式ではなく構造化されたレビューによって
評価される、定義された品質ドメインを中心に編成される:

使いやすさ                   — 対象ユーザーグループにとっての
                             明瞭さ、アクセシビリティ、使用の
                             容易さ
技術的堅牢性/信頼性         — 安定性、パフォーマンス、技術的
                             欠陥からの解放
相互運用性                   — アプリの機能に関連する場合、他の
                             システムとデータを交換する能力
コンテンツの品質と安全性     — 正確性、最新性、有害または誤解を
                             招く健康上の主張の不在
セキュリティとプライバシー   — データ保護の実践とデータ使用に
                             ついての透明性

各ドメインは構造化されたレビュー基準を通じてスコア化され、
全体的な品質評価に組み合わされる。これはいくつかの健康アプリ
品質ラベリングスキームが、公開品質ラベルまたはキュレートされた
ライブラリへの組み入れ決定の技術的基盤として使用する。
```

## 計算例

ある医療システムのデジタルアプリライブラリプログラムは、アプリの選択を完全にアプリストアの検索に任せるのではなく、患者のためのウェルネスアプリの推奨リストをキュレートしたいと考えている。各候補アプリはISO/TS 82304-2のドメインに対して評価される:ある睡眠トラッキングアプリは使いやすさと技術的堅牢性で高いスコアを示し、コンテンツの品質では十分なスコアを示すが、セキュリティとプライバシーのレビュー中に、明確な開示なしにユーザーデータを第三者の広告主と共有していることが判明する——これは、その他の点では強い使いやすさのスコアにもかかわらず、推奨リストからアプリを除外するのに十分重大な発見である。このドメインごとの結果は、単一の統合品質スコアよりも、キュレーションチームとアプリ自体の開発者(共有される場合)の両方にとってより実行可能である。アプリが再検討される前に正確にどの側面を修正する必要があるかを特定するためである。

## データソースと注意点

ISO/TS 82304-2に対する評価は通常、訓練されたレビュアーまたは認定された評価サービスによって、各ドメインの仕様の構造化されたレビュー基準に従って実施される。いくつかの国家的・商業的なイニシアチブ(健康アプリ品質ラベリング・キュレーション組織、一部は正式な国家医療システムの承認の下で運営されている)は、この標準を自社の公開向けアプリ品質ラベルの技術的基盤として使用している——これは、実際にはアプリの「認証済み」または「ラベル付き」ステータスが、特定のラベリングスキームによるその標準の実装を反映していることが多く、必ずしもすべてのスキームで同一のプロセスではないことを意味する。そのため、引用される品質ラベルとともに、特定の評価組織とその方法論を確認し開示すべきである。この仕様はソフトウェアとしてのアプリの品質と基本的な安全性の特性を評価するものであり、アプリの主張や機能が実際に医療機器の閾値を満たす場合の医療機器規制クリアランスの代替ではなく、それを代替として使用することはカテゴリーエラーとなる。

## 落とし穴

- **品質ラベルを規制クリアランスとして扱うこと**: ISO/TS 82304-2の下で評価されラベル付けされたアプリは、それによって医療機器の規制承認を受けたわけではない。両者は異なる目的を果たしており、アプリの説明やマーケティングの方法において決して混同されるべきではない。
- **標準に基づくすべてのラベリングスキームが同等であると仮定すること**: 異なる組織は、独自の特定のレビュープロセスと厳格さでISO/TS 82304-2に基づく評価を実施する。「ISO/TS 82304-2に基づく」ラベルを別のものと互換性があるものとして扱うのではなく、どの組織がどのように評価を実施したかを確認すること。
- **セキュリティとプライバシーを軽視して使いやすさのみを評価すること**: 使いやすさの問題はエンドユーザーにとって最も目に見えやすく、非公式に評価するのが最も簡単であるため、レビュアーが、目に見えにくいが潜在的により重大な結果をもたらすセキュリティとプライバシーのドメインを過小評価することにつながる可能性がある。
- **評価を一度限りの永続的な認証として扱うこと**: アプリのコンテンツ、セキュリティの実践、第三者とのデータ共有の取り決めはすべて初期評価後に変化しうる。信頼できる品質ラベリングプログラムは、初期の合格を永続的なものとして扱うのではなく、定期的に再評価する。
