# デジタルリテラシー率

デジタルリテラシー率は、患者集団のうち、デジタルヘルスプラットフォーム上の一般的なタスク——ログイン、予約のスケジューリング、ビデオ訪問への参加、検査結果の閲覧など——を、他者の支援を必要とせずに独立して成功裏に完了できる割合を測定する。これはデジタルアクセス率とは異なり、常に別々に測定されるべきである:患者はスマートフォンとブロードバンド接続を持ちながらも、支援なしにテレヘルスプラットフォームをナビゲートできないことがあり、この2つの指標を混同することは、まさにこの指標が明らかにするために存在する集団を隠してしまう。

## なぜ重要か

デジタルアクセスだけでは、患者がデジタルヘルスサービスを効果的に使用できることを保証しない:健康リテラシーが低い、一般的にテクノロジーの経験が限られている、認知的または視覚的障害がある、あるいはプラットフォームのインターフェース言語に言語的障壁がある患者は、完全な技術的アクセスを持ちながらも、独立してタスクを完了できないことがある。このギャップは、すでに他の健康格差に直面している同じ人口統計グループと体系的に相関している。HIMSS Digital Health Equity Measurement Frameworkは、まさにこの理由でデジタルリテラシーをアクセスとは別個の柱として扱う:リテラシーのギャップに対処せずにアクセスのギャップを埋めることは、技術的には接続されているが機能的には恩恵を受けられない集団を残す可能性がある。言語と社会経済的指標でセグメント化して一般的なプラットフォーム操作のタスク完了と完了までの時間を測定する組織は、アクセス指標や全体的な満足度スコアだけに頼る組織よりもはるかに正確にリテラシーの障壁を特定し、支援(簡略化されたインターフェース、支援付きオンボーディング、代替言語コンテンツ)を対象化することができる。

## 算出方法

```
デジタルリテラシー率 = 支援なしに独立して定義されたタスクを
                      完了する患者数 / そのタスクを試みる
                      患者数 × 100

測定される一般的なタスク: アカウントログイン、予約スケジュー
リング、ビデオ訪問への参加、検査結果の閲覧、受付フォームの
完了。

単一の統合スコアとしてではなく、タスクごとに報告すること。
単純なタスク(ログイン)と複雑なタスク(複数ステップの受付
フォームの完了)のリテラシーは大きく異なり、それらを混ぜる
と特定の障壁がどこにあるかが不明瞭になるためである。
```

## 計算例

ある医療システムが、月間5,000件の予定されたテレヘルス予約にわたって、ビデオ訪問への参加を定義されたタスクとして追跡している。このうち4,100人の患者が、サポートコールや訪問中の技術的支援なしに成功裏に参加する(このタスクのデジタルリテラシー率:82%)。主要言語別にセグメント化すると、英語を話す患者では89%の率であるのに対し、主要言語がプラットフォームのデフォルトインターフェース言語と異なる患者では61%であり、この28ポイントのギャップは、統合された82%の数値のみが報告された場合には見えなくなり、曖昧な一般的なリテラシーの問題ではなく、特定の対処可能な介入(翻訳されたインターフェースと指示)を直接指し示すものである。

## データソースと注意点

タスク完了データは通常、プラットフォーム自体のイベントログ(患者がビデオ訪問に到達したか、予約スケジューリングフローが放棄なしに完了したか)から取得され、サポートコールやヘルプデスクの連絡データで補完され、患者が途中でライブ支援を受けたことによって技術的に「完了」したタスクを特定する。システムログのみからカウントされた「完了」タスクは、患者がそこに到達するために家族やサポートスタッフからの電話が必要だったことを隠してしまう可能性がある——真にリテラシーに依存しない完了は、プラットフォームが両者を区別できる限り、支援付き完了とは別に定義され追跡されるべきである。デジタルリテラシーは健康リテラシーや一般的なリテラシーと相関するが、分析的には区別される。正式な評価が必要な場合はいつでも、年齢や人口統計だけに基づく非公式な仮定ではなく、検証済みの道具を使用すべきである。

## 落とし穴

- **デジタルリテラシーをデジタルアクセスと混同すること**: 完全な技術的アクセスを持つ患者でも、それを効果的に使用するリテラシーが欠けていることがある。これらは別々の介入を必要とする別々の指標であり、決して単一の統合数値として報告すべきではない。
- **支援付き完了を支援なしの成功としてカウントすること**: 患者がサポートコールや家族の助けを借りてのみタスクを完了する場合、それはプラットフォームが覆い隠したリテラシーのギャップであり、解決されたものではない。データが許す限り、支援付き完了と支援なし完了を区別すること。
- **単一の統合タスク完了スコアを報告すること**: 単純なタスク(ログイン)と複雑なタスク(詳細な受付フォームの完了)のリテラシーは大きく異なる。障壁が正確にどこにあるかを特定するために、タスクごとに報告すること。
- **年齢だけがデジタルリテラシーを予測すると仮定すること**: 年齢は集計レベルでは低いデジタルリテラシーと相関するが、プラットフォームのインターフェース言語における言語能力と一般的なテクノロジーへの親しみは、しばしばより強い個別の予測因子であり、年齢から推測するのではなく直接測定されるべきである。
