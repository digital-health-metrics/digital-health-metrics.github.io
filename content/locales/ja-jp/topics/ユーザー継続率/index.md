# ユーザー継続率

ユーザー継続率とは、開始期間にアクティブだったユーザーのうち、後の期間でもアクティブであり続ける割合であり、その逆数であるチャーン(離脱)率は、製品の使用を完全にやめる割合である。患者ポータル採用率(その項目を参照)が患者がデジタルヘルス製品を意味のある形で一度でも有効化したかどうかを測定するのに対し、継続率は彼らが使い続けているかどうかを測定する——サブスクリプション型または継続的ケア型のデジタルヘルス製品にとって、継続率は通常、臨床的インパクトと商業的持続可能性の両方に最も密接に結びついた単一の指標である。

## なぜ重要か

ユーザーを維持できないデジタルヘルス製品は、初期の採用や有効化の数値がどれほど強くても、持続的な臨床的利益をもたらすことができない。2週間使用された後に放棄される慢性疾患管理ツールは、数か月間の持続的な行動変化に依存するバイオメトリック成果を動かす可能性は低い。継続率はまた、デジタルヘルス企業が投資家や支払者に報告する最も商業的に重要な指標の1つでもある。なぜなら、継続曲線(単一の継続率パーセンテージだけでなく、時間の経過に伴う低下の形状)は、製品が真に持続可能な使用パターンを見出したのか、単に予測可能に薄れていく新奇性主導の初期の関心を捉えているだけなのかを明らかにするからである。初期の低下の後に平坦化する継続曲線(最初の月を乗り越えた患者は留まる傾向がある)は、底なしで着実に低下し続ける曲線とは非常に異なる、はるかに健全なシグナルである。

## 算出方法

```
継続率(期間N) = 開始コホート期間にもアクティブだった、期間N
                にアクティブなユーザー数 / 開始コホート期間の
                ユーザー数 × 100

チャーン率 = 1 − 継続率(同じ期間について)

単一時点の数値ではなく、コホート継続曲線(日/週/月1、2、3…
での継続)として報告すること。単一のスナップショットは、まだ
チャーンする機会がなかった最近参加したユーザーと、長期在籍
ユーザーを混同してしまうためである。
```

## 計算例

あるデジタルヘルスアプリが1月に1,000人の新規ユーザーのコホートを登録する。月1の終わりまでに、元の1,000人のうち640人がまだアクティブである(月1継続率64%)。月3の終わりまでに、410人がアクティブのままである(月3継続率41%)。月6までに、380人がアクティブのままである(月6継続率38%)。この曲線の形状——急激な初期低下とその後の月3から月6にかけての平坦化——は、製品が最初の採用のハードルを乗り越えると安定したコアユーザーを維持することを示唆しており、これは月3から月6への低下が月1から月3と同じ率で続いていた場合よりも、物質的に異なり、より有望なシグナルである。

## データソースと注意点

継続率は製品自体のログインまたはアクティビティイベントログから計算され、比較されるすべてのコホートにわたって「アクティブ」を一貫して定義する(例えば、その期間内に少なくとも1回の該当するセッション)。コホートは同等の基準で比較されるべきである——同じ「アクティブ」の開始定義、同じ長さの観察ウィンドウ——30日対28日の月や、より厳格対より緩い「アクティブ」閾値といった小さな定義上の違いでさえ、ユーザー行動に実際の違いがなくても、報告される継続率のパーセンテージを数ポイント変動させる可能性があるためである。季節効果は、新年の抱負や特定の健康啓発期間に関連する健康アプリでは一般的であるため、異なる時期から取得されたコホートを比較するよりも、年次比較の方が通常より有益である。

## 落とし穴

- **曲線ではなく単一の継続率スナップショットを報告すること**: 時間の経過に伴う低下の形状がない「ユーザーのX%がまだアクティブ」という単一の数値では、横ばいになる製品(健全)と継続的に低下する製品(不健全)を区別できない。
- **報告期間間で「アクティブ」の定義を変更すること**: アクティブユーザーの定義を緩めること(例えば、完了したアクションではなく受動的なアプリの起動をカウントすること)は、実際の利用がまったく変化していなくても継続率が改善しているように見せる可能性がある。
- **コホートの季節性を無視すること**: 1月のコホートの継続率(新年の抱負による登録によってしばしば水増しされ、平均してモチベーションの低いコホートをもたらす)を、年の異なる時期に獲得されたコホートと比較すると、誤解を招くトレンドの結論を生む可能性がある。
- **有機的獲得と有料獲得のコホートを混ぜること**: 異なるチャネルを通じて獲得されたユーザーは、しばしば非常に異なる継続をする。それらを1つの集計継続率に混ぜると、チャネル特有の継続の問題を隠してしまう可能性がある。
