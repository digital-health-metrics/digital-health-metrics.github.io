# デバイス稼働率

デバイス稼働率は、接続された健康デバイス——遠隔患者モニタリングセンサー、ウェアラブル、または在宅テレヘルスユニット——が、オフライン、切断、または誤動作している時間ではなく、実際にオンラインでデータを送信し正しく機能している予定モニタリング時間の割合を測定する。これはあらゆる遠隔モニタリングまたは接続デバイスプログラムの基礎となるインフラ指標である:頻繁にオフラインだったデバイスから計算された臨床アラート、バイオメトリックトレンド、またはエンゲージメント数値は、その背後にある接続性と同程度にしか信頼できない。

## なぜ重要か

遠隔患者モニタリングプログラムの臨床的価値提案全体は、継続的またはほぼ継続的なデータ取得に依存している。稼働率の低いデバイスは、患者の臨床像に静かなギャップを作り出し、それが(モニタリングの失敗として正しく識別されるのではなく)安定性と誤認される可能性がある(データがないためにアラートがない、何も変わっていないからではない)。デバイス稼働率はまた、プログラムのコストと患者体験の先行指標でもある:頻繁に接続を失うデバイスは、サポートコール、患者の不満、そしてデータギャップが本物の臨床イベントを反映しているのか単なる技術的な不具合なのかを確認するための潜在的に不必要な臨床的アウトリーチを生み出す。デバイス稼働率の失敗は、患者ではなく組織が制御するインフラ(不適切に設定されたセルラーゲートウェイ、患者宅での弱いWi-Fiカバレッジ、保守が不十分なデバイスフリート)に起因することが多いため、この指標は患者エンゲージメント指標に無差別に組み込むのではなく、ベンダーと技術運用チームに明確に帰属すべきである。

## 算出方法

```
デバイス稼働率 = デバイスがオンラインで有効なデータを送信して
                いた時間 / 総予定モニタリング時間 × 100

データが許す限り、ダウンタイムの根本原因をセグメント化すること:
  デバイス側の故障      (バッテリー、ハードウェア障害、
                        ファームウェアクラッシュ)
  接続性の故障          (セルラー/Wi-Fi/VPNの切断)
  患者側の要因          (デバイスの電源オフ、範囲外への移動)

稼働率とともに追跡すべき補助的な技術パラメータ:
  デバイスあたりの平均CPU使用率、メモリ使用量、バッテリー
  レベル
  接続障害間の平均時間
  切断後に再接続するまでの平均時間
```

## 計算例

ある遠隔心臓モニタリングプログラムが1,000台の接続デバイスを展開し、それぞれが継続的に送信することが期待されている。30日間の月(デバイスあたり予定モニタリング時間720時間)で、フリート全体は予定された720,000時間に対して合計705,600時間の実際のオンライン時間を記録し、フリート全体のデバイス稼働率は705,600 / 720,000 × 100 = 98%となる。14,400時間のダウンタイムの根本原因分析によると、60%は特定の農村サービス地域に集中したセルラー接続の切断に起因し、25%は交換対象としてフラグ付けされた老朽化したバッテリーを持つデバイスに起因し、15%は患者が一時的にデバイスの電源を切ったことに起因する。この内訳は、単一の集計稼働率数値では区別できなかったであろう、2つの明確で異なる介入——影響を受ける地域の接続性修正と積極的なバッテリー交換プログラム——を指し示している。

## データソースと注意点

稼働率データは、デバイスごとの接続とハートビートイベントを記録する、デバイスメーカーまたはプラットフォームベンダー自身のデバイス管理・テレメトリシステムから得られる。組織は、ベンダーが「オンライン」として何をカウントしているかを正確に確認すべきである(デバイスは、有効な臨床データの送信に失敗しながらも、ネットワークに接続していると自己報告することがあり、これはベンダー自身のダッシュボードが接続していると報告していても、臨床目的ではダウンタイムとしてカウントされるべきである)。稼働率は、ボリュームが許す限りデバイスコホートまたは地域ごとに報告されるべきである。接続性の品質は、患者集団全体に均等に分布しているのではなく、しばしば地理的に集中している(農村部のセルラーカバレッジ、古い建物のWi-Fi)ためであり、集計されたフリート全体の数値は、深刻で対処可能な地域の問題を隠してしまう可能性がある。

## 落とし穴

- **ネットワーク接続と有効なデータ送信を混同すること**: デバイスはベンダーのダッシュボード上で「接続されている」ように見えながら、使用可能な臨床データの送信に失敗することがある。稼働率は、生のネットワーク接続性だけではなく、実際の有効なデータ受信に対して定義し測定すること。
- **フリート全体の平均のみを報告すること**: これは、対象を絞った平均によって明らかになる深刻で地理的またはデバイスコホート特有のダウンタイムの問題を隠してしまう可能性があり、それには特定の対処可能な修正がある。
- **ダウンタイムの根本原因を区別しないこと**: デバイス側、接続性、患者側のダウンタイムはそれぞれ完全に異なる介入を必要とする。根本原因のセグメント化なしの単一のダウンタイムパーセンテージでは行動を起こせない。
- **データギャップをデフォルトで臨床的安定性として扱うこと**: オフラインデバイスからのデータストリームの欠落は、技術的接続性チェックをトリガーすべきであり、患者の臨床状態について「便りがないのは良い便り」として黙って解釈されるべきではない。
