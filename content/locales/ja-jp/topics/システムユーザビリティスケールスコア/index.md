# システムユーザビリティスケールスコア

システムユーザビリティスケール(SUS)スコアは、ソフトウェアの使いやすさを定量化するために使用される標準化された10項目の質問票であり、確立された業界標準に照らしてベンチマークできる0から100の単一スコアを生成する。推薦意欲を測定するネットプロモータースコアや、臨床的・機能的状態を測定する患者報告アウトカム指標とは異なり、SUSは1つの特定のことを測定する:そのソフトウェア自体が、患者であれ臨床スタッフであれ、学習し使用するのがどれほど容易かということである。

## なぜ重要か

デジタルヘルスツールは、患者や臨床医がインターフェースを混乱させる、遅い、または使用するのにイライラすると感じるために、強力な臨床的エビデンスと説得力のあるビジネスケースを持ちながらも実際には失敗することがある——そしてSUSは、業界全体にわたる数十年の公開されたベンチマークデータを持つ検証済みの広く使用されている道具であるため、デジタルヘルスチームは、非公式な印象や逸話的な苦情に頼るのではなく、自社製品のユーザビリティを既知の分布と比較することができる。SUSは意図的に技術に依存せず、迅速に実施できる(通常5分未満)ため、完全なユーザビリティ研究や正式な臨床試験とは異なり、デザインの反復全体にわたって繰り返し実行することが実用的である。臨床医向けのユーザビリティの失敗はバーンアウトの文書化された要因であり(医師バーンアウト率を参照)、患者向けのユーザビリティの失敗は放棄とデジタルリテラシーの低い成果の文書化された要因であるため(デジタルリテラシー率を参照)、SUSは、それらのより深刻な下流指標に現れる前にデザイン上の問題を捕捉できる、低コストの早期警告ユーザビリティシグナルとして機能する。

## 算出方法

```
SUSスコア = ((奇数項目のスコアの合計 − 5) +
            (25 − 偶数項目のスコアの合計)) × 2.5

結果は0から100の単一スコアである(「正答率」などを表すもの
ではないため、尺度にもかかわらずパーセンテージではない)。

公開されたベンチマーク解釈(Bangorら):
  80以上   — 優れたユーザビリティ
  68       — 広範な業界標準に基づく平均
  51未満   — 不良なユーザビリティ、調査が必要
```

## 計算例

あるテレヘルスプラットフォームが、初回のビデオ訪問後に150人の患者に標準的な10項目のSUS質問票を実施する。全回答者にわたる計算された平均SUSスコアは74である。広く引用される業界平均68に照らしてベンチマークすると、この特定の患者集団とユースケースにとって平均を上回るユーザビリティを示しているが、残りのユーザビリティ障壁がほとんどないことを示唆する「優れた」閾値の80には依然として意味のあるほど届いていない。同じ150件の回答を年齢別に分けると、50歳未満の患者の平均スコアは81、65歳以上の患者は62であり、これは単一の統合平均が隠してしまう、高齢患者にとっての一般的な製品ユーザビリティの問題ではなく、特定の対処可能なユーザビリティの問題を示すギャップである。

## データソースと注意点

SUSデータは、標準化された10項目の質問票を完了する患者や臨床医から直接得られ、結果として得られるスコアが公開されたベンチマークと比較可能であるためには、その道具が検証された通りに正確に実施されなければならない(同じ10項目、同じ5段階の同意尺度、同じスコアリング式)。どれほど善意であっても、質問票の修正版や短縮版は、標準ベンチマーク分布に対して信頼性高く解釈できないスコアを生み出す。SUSは知覚されたユーザビリティを測定するものであり、これは客観的なタスク完了の成功と相関するが同一ではない(タスク完了ベースの測定についてはデジタルリテラシー率を参照)。製品は、より複雑な機能を試みなかった患者から良いSUSスコアを得ることができるため、SUSを客観的なタスク完了データと組み合わせることで、どちらか一方だけよりも完全な全体像を得ることができる。回答のタイミングも重要である。フラストレーションのたまる特定のインシデント(接続の失敗、わかりにくいステップ)の直後にSUSを実施することと、円滑なセッションの後に実施することでは、製品全体のユーザビリティとは無関係にスコアが変動する可能性がある。

## 落とし穴

- **標準質問票の項目やスコアリングを修正すること**: わずかな文言や尺度の変更でさえ、確立された公開ベンチマーク分布との比較を無効にする。検証された通りに正確に標準的な10項目の道具を使用すること。
- **セグメント化せずに平均スコアのみを報告すること**: ユーザビリティはしばしばユーザーの年齢、デジタルリテラシー、役割(患者対臨床医)によって大きく異なる。単一の平均が隠してしまう特定の対処可能なユーザビリティのギャップを見つけるために、報告をセグメント化すること。
- **SUSを臨床的有効性の尺度として扱うこと**: SUSは特にユーザビリティを測定するものであり、臨床転帰やケアへの満足度ではない。非常に使いやすいツールでも臨床転帰を改善できないことがあり、これらを決して混同したり互いに代用したりすべきではない。
- **異常に円滑な、または異常にフラストレーションのたまるセッションの後にのみ調査を実施すること**: 実施のタイミングと文脈はスコアを偏らせる可能性がある。便宜的または選択的に選ばれたセッションだけでなく、実世界のセッションの代表的なサンプル全体にわたって一貫して実施すること。
