# 设备正常运行率

设备正常运行率是指联网健康设备——远程患者监测传感器、可穿戴设备，或居家远程医疗设备——在计划监测时间内实际在线、传输数据并正常运作，而非离线、断开连接或发生故障的时间比例。这是每一个远程监测或联网设备项目背后的基础基础设施指标：一份根据经常离线的设备计算出的临床警报、生物指标趋势或参与度数字，其可靠性仅取决于其背后的连接性。

## 为何重要

远程患者监测项目的整个临床价值主张，都依赖于持续或近乎持续的数据采集；正常运行率低的设备会在患者的临床画面中制造无声的缺口，这些缺口可能被误认为是病情稳定（因为没有数据而没有警报，而非因为没有发生变化），而非被正确识别为监测失败。设备正常运行率也是项目成本与患者体验的领先指标：频繁断开连接的设备会产生支持电话、患者挫折感，以及可能不必要的临床外联，以核实数据缺口究竟反映的是真实临床事件，还是仅仅是技术故障。由于设备正常运行率故障通常可归因于机构所控制的基础设施（配置不当的蜂窝网关、患者家中较弱的Wi-Fi信号覆盖、维护不善的设备机队），而非患者本身，这项指标明确属于供应商和技术运营团队的职责，不应不加区分地并入患者参与度指标。

## 计算方法

```
设备正常运行率 = 设备在线并传输有效数据的时间 /
                  计划监测总时间 × 100

在数据允许的情况下，对停机根本原因进行细分：
  设备端故障   （电池、硬件故障、固件崩溃）
  连接故障     （蜂窝/Wi-Fi/VPN中断）
  患者端因素   （设备被关闭、移出信号范围）

需一并追踪的辅助技术参数：
  每台设备的平均CPU利用率、内存使用率和电池电量
  连接故障之间的平均时间间隔
  中断后重新连接的平均时间
```

## 实例解析

某远程心脏监测项目部署了1000台联网设备，每台设备预期持续传输数据。在一个30天的月份内（每台设备计划监测720小时），该设备机队记录的实际在线时间总计为705600小时，占计划的720000小时，机队整体设备正常运行率为705600 / 720000 × 100 = 98%。对14400小时停机时间的根本原因分析显示，60%可归因于集中在某个特定农村服务区域的蜂窝连接中断，25%可归因于被标记待更换的老化电池设备，15%可归因于患者暂时关闭设备。这一细分指向了两项明确、不同的干预措施——针对受影响区域的连接修复，以及主动的电池更换计划——而单一的综合正常运行率数字无法区分这两者。

## 数据来源与注意事项

正常运行率数据来自设备制造商或平台供应商自身的设备管理与遥测系统，该系统记录每台设备的连接与心跳事件；机构应确认供应商所计算的"在线"具体含义（设备可能报告自己已连接到网络，但未能传输有效的临床数据，而这一情况应在临床意义上计为停机时间，即使供应商自身的仪表盘将其报告为已连接）。在数据量允许的情况下，应按设备群组或地理区域分别报告正常运行率，因为连接质量往往在地理上集中（农村蜂窝覆盖、较老建筑的Wi-Fi），而非在患者人群中均匀分布，机队整体的综合数字可能掩盖一个严重的、可解决的区域性问题。

## 常见误区

- **将网络连接与有效数据传输混为一谈**：设备可能在供应商仪表盘上显示"已连接"，却未能传输可用的临床数据；应根据实际有效数据接收情况，而非仅根据原始网络连接性，来定义和测量正常运行率。
- **仅报告机队整体平均值**：这可能掩盖一个严重的、地理或设备群组特定的停机问题，而有针对性的平均值本可揭示该问题并找到具体、可解决的方案。
- **未区分停机的根本原因**：设备端、连接和患者端停机各自需要完全不同的干预措施；没有根本原因细分的单一停机百分比无法据此采取行动。
- **默认将数据缺口视为临床稳定**：来自离线设备的数据流缺失应触发技术连接性检查，而不应被默默解读为患者临床状态"没有消息就是好消息"。
