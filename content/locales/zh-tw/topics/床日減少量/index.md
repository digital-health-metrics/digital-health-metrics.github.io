# 床日減少量

床日減少量衡量的是透過將特定護理事件——最常見的是術後恢復或急性病情管理——從傳統住院轉移至虛擬病房或居家醫院等數位支援替代方案，所避免的住院床日總數。這是虛擬病房和居家醫院專案的核心容量指標，將臨床護理模式的改變直接轉化為醫院營運和系統規劃者實際管理的貨幣（床位容量）。

## 為何重要

住院床位容量是任何醫院系統中最受限、最昂貴的資源之一，虛擬病房或居家醫院專案的核心價值主張在於：它能夠在不佔用實體床位的情況下安全地提供特定水平的臨床護理，從而釋放該容量以服務無法以其他方式得到管理的病患。床日減少量將一個通常抽象的主張（"這個專案改善了護理"）轉化為醫院容量規劃者、財務團隊和委託方可以直接採取行動的具體營運數位：它可用於建模對監測專案的投資是否能在避免的床位成本中收回，以及回收多少。由於床日減少量只有在維持病患安全的前提下才有價值，因此應始終與安全結果指標（如再入院率或轉為住院護理的比率）一併報告，而絕不應單獨報告。

## 計算方法

```
床日減少量 = 標準住院護理下的預期床日數（基於配對病患
              佇列的歷史住院時長資料）− 虛擬/數位路徑
              病患實際使用的床日數

應按臨床路徑分別報告（例如術後恢復、急性呼吸系統病情加
重），因為預期住院時長因病情而異極大，跨越不相關路徑
的混合數位沒有意義。
```

## 實例解析

某醫院的歷史資料顯示，接受特定擇期手術的病患平均住院時長為4天。一個虛擬病房專案招募了150名接受同一手術的病患，平均在1.5個住院日後出院，其餘恢復期透過遠端監測進行。床日減少量為(4 − 1.5) × 150 = 375床日，涵蓋測量期。該數位應與同一150名病患的30天轉為住院護理率和再入院率一併報告，因為以顯著更高的轉院率或再入院率為代價換取的床日節省，並非頭條數位所暗示的臨床勝利。

## 資料來源與注意事項

預期床日數需要一個可信的歷史基線，理想情況下來自在臨床特徵（年齡、合併症、手術型別、嚴重程度）上與虛擬病房人群相匹配的、接受標準住院護理的病患佇列，因為與未匹配的歷史平均值進行比較，若數位管理佇列在系統性上更健康或更嚴重，就有誇大或低估真實減少量的風險。數位路徑上實際使用的床日數來自醫院自身的入院-出院-轉院（ADT）系統；在監測恢復期間任何轉回住院護理的情況，都應誠實地計入該專案（作為已使用的床日，而非被排除），因為將轉院情況排除在計算之外會人為地虛增表觀減少量。

## 常見誤區

- **報告床日減少量卻沒有匹配的安全性比較**：一個節省了床日但轉院率或再入院率明顯更差的虛擬病房，並未真正展示出改善；應始終將兩者一併報告。
- **使用未匹配或過時的歷史基線**：與病例組合、合併症負擔或臨床實踐時代不同的歷史佇列進行比較，可能會顯著誇大或低估真實的床日節省量。
- **將轉回住院護理的情況排除在計算之外**：接受虛擬監測但在恢復過程中轉為住院床位的病患，其床日應計入該專案，而不應被悄悄從分析中剔除。
- **合併預期住院時長差異很大的路徑**：將床日減少量跨臨床不相關的路徑彙總（例如將術後恢復與慢性呼吸道管理合併）成一個數位，會掩蓋究竟是哪條特定路徑帶來了節省。
