# 裝置正常運作率

裝置正常運作率是指聯網健康裝置——遠端病患監測感測器、可穿戴裝置，或居家遠距醫療裝置——在計劃監測時間內實際線上、傳輸資料並正常運作，而非離線、斷開連線或發生故障的時間比例。這是每一個遠端監測或聯網裝置專案背後的基礎基礎設施指標：一份根據經常離線的裝置計算出的臨床警報、生物指標趨勢或參與度數位，其可靠性僅取決於其背後的連線性。

## 為何重要

遠端病患監測專案的整個臨床價值主張，都依賴於持續或近乎持續的資料採集；正常運作率低的裝置會在病患的臨床畫面中製造無聲的缺口，這些缺口可能被誤認為是病情穩定（因為沒有資料而沒有警報，而非因為沒有發生變化），而非被正確識別為監測失敗。裝置正常運作率也是專案成本與病患體驗的領先指標：頻繁斷開連線的裝置會產生支援電話、病患挫折感，以及可能不必要的臨床外聯，以核實資料缺口究竟反映的是真實臨床事件，還是僅僅是技術故障。由於裝置正常運作率故障通常可歸因於機構所控制的基礎設施（配置不當的蜂窩閘道器、病患家中較弱的Wi-Fi訊號覆蓋、維護不善的裝置機隊），而非病患本身，這項指標明確屬於供應商和技術營運團隊的職責，不應不加區分地併入病患參與度指標。

## 計算方法

```
裝置正常運作率 = 裝置線上並傳輸有效資料的時間 /
                  計劃監測總時間 × 100

在資料允許的情況下，對停機根本原因進行細分：
  裝置端故障   （電池、硬體故障、韌體崩潰）
  連線故障     （蜂窩/Wi-Fi/VPN中斷）
  病患端因素   （裝置被關閉、移出訊號範圍）

需一併追蹤的輔助技術引數：
  每臺裝置的平均CPU利用率、記憶體使用率和電池電量
  連線故障之間的平均時間間隔
  中斷後重新連線的平均時間
```

## 實例解析

某遠端心臟監測專案部署了1000臺聯網裝置，每臺裝置預期持續傳輸資料。在一個30天的月份內（每臺裝置計劃監測720小時），該裝置機隊記錄的實際線上時間總計為705600小時，佔計劃的720000小時，機隊整體裝置正常運作率為705600 / 720000 × 100 = 98%。對14400小時停機時間的根本原因分析顯示，60%可歸因於集中在某個特定農村服務區域的蜂窩連線中斷，25%可歸因於被標記待更換的老化電池裝置，15%可歸因於病患暫時關閉裝置。這一細分指向了兩項明確、不同的介入措施——針對受影響區域的連線修復，以及主動的電池更換計劃——而單一的綜合正常運作率數位無法區分這兩者。

## 資料來源與注意事項

正常運作率資料來自裝置製造商或平臺供應商自身的裝置管理與遙測系統，該系統記錄每臺裝置的連線與心跳事件；機構應確認供應商所計算的"線上"具體含義（裝置可能報告自己已連線到網路，但未能傳輸有效的臨床資料，而這一情況應在臨床意義上計為停機時間，即使供應商自身的儀表盤將其報告為已連線）。在資料量允許的情況下，應按裝置群組或地理區域分別報告正常運作率，因為連線品質往往在地理上集中（農村蜂窩覆蓋、較老建築的Wi-Fi），而非在病患人群中均勻分佈，機隊整體的綜合數位可能掩蓋一個嚴重的、可解決的區域性問題。

## 常見誤區

- **將網路連線與有效資料傳輸混為一談**：裝置可能在供應商儀表盤上顯示"已連線"，卻未能傳輸可用的臨床資料；應根據實際有效資料接收情況，而非僅根據原始網路連線性，來定義和測量正常運作率。
- **僅報告機隊整體平均值**：這可能掩蓋一個嚴重的、地理或裝置群組特定的停機問題，而有針對性的平均值本可揭示該問題並找到具體、可解決的方案。
- **未區分停機的根本原因**：裝置端、連線和病患端停機各自需要完全不同的介入措施；沒有根本原因細分的單一停機百分比無法據此採取行動。
- **預設將資料缺口視為臨床穩定**：來自離線裝置的資料流缺失應觸發技術連線性檢查，而不應被默默解讀為病患臨床狀態"沒有訊息就是好訊息"。
