# 系统可用性量表得分

系统可用性量表（SUS）得分是一份标准化的10项问卷，用于量化一款软件的可用性，产生一个0到100的单一分数，可与成熟的行业规范进行基准比较。与衡量推荐意愿的净推荐值，或衡量临床或功能状态的患者报告结局测量不同，SUS衡量的是一件特定的事情：无论对患者还是临床工作人员而言，该软件本身有多容易学习和使用。

## 为何重要

一款数字健康工具即使拥有强有力的临床证据和有说服力的商业案例，也可能因为患者或临床医生觉得其界面令人困惑、缓慢或使用起来令人沮丧而在实践中失败——由于SUS是一种经过验证、被广泛使用的工具，拥有数十年跨行业发布的基准数据，它使数字健康团队能够将自己产品的可用性与已知分布进行比较，而非依赖非正式印象或偶发投诉。SUS在设计上与具体技术无关，且施测迅速（通常不到五分钟），这使其便于在设计迭代过程中反复施测，不同于完整的可用性研究或正式的临床试验。由于面向临床医生的可用性问题已被记录为职业倦怠的一个促成因素（参见医生职业倦怠率），面向患者的可用性问题已被记录为放弃使用和数字素养结果不佳的促成因素（参见数字素养率），SUS作为一种早期、低成本的可用性信号，能够在设计问题出现在那些更具后果性的下游结果指标之前将其发现。

## 计算方法

```
SUS得分 = ((奇数项得分之和 − 5) +
          (25 − 偶数项得分之和)) × 2.5

结果是一个0到100的单一分数（而非百分比，尽管使用了该量
表，因为它并不代表"正确百分比"或类似含义）。

已发布的基准解读（Bangor等）：
  高于80  —— 可用性优秀
  68      —— 平均水平，基于广泛的行业规范
  低于51  —— 可用性较差，需要调查
```

## 实例解析

一个远程医疗平台在150名患者首次视频问诊后对其施测标准的10项SUS问卷。所有受访者计算出的平均SUS得分为74。以广泛引用的68分行业平均值为基准，这表明该特定患者群体和使用场景的可用性高于平均水平，但仍在"优秀"阈值80分以下，这意味着仍有一些值得关注的可用性障碍。按年龄细分同样的150份答复显示，50岁以下患者的平均得分为81，65岁及以上患者为62——这一差距指向了一个针对老年患者的具体、可解决的可用性问题，而非一个笼统的产品可用性问题，而单一的合并平均值将掩盖这一点。

## 数据来源与注意事项

SUS数据直接来自患者或临床医生完成标准化的10项问卷，必须完全按照经过验证的方式施测该工具（相同的10个项目、相同的5点一致性量表、相同的计分公式），所得分数才能与已发布的基准进行比较；无论出发点多好，对问卷进行修改或缩短版本，都会产生一个无法与标准基准分布可靠对照解读的分数。SUS衡量的是感知可用性，它与客观任务完成成功率相关但并不相同（参见数字素养率，了解基于任务完成的衡量方式）；一款产品可能从未尝试更复杂功能的患者那里获得良好的SUS得分，因此将SUS与客观任务完成数据配对，能比单独使用任何一项都提供更完整的图景。

## 常见误区

- **修改标准问卷项目或计分方式**：即使是微小的措辞或量表变化，也会使与既定的已发布基准分布进行的比较失效；应完全按照经过验证的方式使用标准的10项工具。
- **仅报告平均分而不进行细分**：可用性通常因用户年龄、数字素养或角色（患者与临床医生）而显著不同；应对报告进行细分，以找出单一平均值所掩盖的具体、可解决的可用性差距。
- **将SUS视为临床有效性的衡量指标**：SUS专门衡量可用性，而非临床结果或护理满意度；一款高度可用的工具仍可能未能改善临床结果，二者绝不应被混淆或相互替代。
- **仅在异常顺畅或异常令人沮丧的会话后施测调查**：施测的时机和情境可能使分数产生偏差；应在具有代表性的真实会话样本中一致地施测，而非仅在方便或经过选择性挑选的会话后施测。
