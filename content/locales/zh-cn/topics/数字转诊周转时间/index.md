# 数字转诊周转时间

数字转诊周转时间是指从转诊临床医生提交电子转诊，到接诊服务方完成分诊并作出接受、拒绝或预约决定之间经过的时间。这是一项流程（流转）指标，不同于患者总体等待时间，也是最能清楚证明数字化系统变革（结构化电子转诊、基于影像的分诊、标准化转诊表单）能够改变运营数字、而不仅仅是满意度分数的领域之一。

## 为何重要

缓慢或高度不稳定的分诊环节，会在患者甚至尚未进入临床候诊名单之前就增加延误，而由于这种延误发生在任何临床诊疗开始之前，它是纯粹的流程浪费，而数字化工具恰好非常适合消除这种浪费。要求"退回转诊方"以补充缺失信息的转诊系统，会产生返工循环，如果只统计第一次就顺利通过的转诊的周转时间，这种返工循环很容易被忽视。当某项服务引入了结构化数字转诊表单、必填字段，或基于影像的分诊（例如远程皮肤科）时，周转时间通常是证明其效益最有说服力的单一指标，因为它可以在变革前后用同一套统计方式加以衡量。

## 计算方法

```
周转时间 = 分诊决定的时间戳 − 转诊提交的时间戳

应报告中位数和一个较高的百分位数（通常为第 90 百分位），
而不仅仅是均值，因为被退回或复杂的转诊会使分布严重右偏。

在系统能够记录的情况下，考虑各子阶段的用时：
  提交 → 服务方接收
  接收 → 分诊决定
  分诊决定 → 预约成功（如适用）
```

## 实例解析

某电子转诊系统的审计记录显示，各专科从提交到分诊决定的中位时间为 1.8 天，第 90 百分位时间为 6 天，主要由于因缺少临床信息而被退回转诊方的转诊所致。同一平台上采用基于影像分诊的远程皮肤科路径，中位周转时间为 4 小时，第 90 百分位为 1 天，因为一张照片和结构化病史几乎总是足以作出分诊决定，无需进一步往返沟通。

## 数据来源与注意事项

电子转诊或转诊管理系统自身的审计记录是主要数据来源，依据提交和决定的时间戳；机构应确认在转诊因需要更多信息而被退回期间，"计时"是暂停还是持续运行，因为这两种定义会对同一底层流程得出实质性不同的数字。周转时间应统一以自然日或工作时长报告，因为周末和节假日效应否则会扭曲工作模式不同的服务之间的比较。

## 常见误区

- **只统计"干净"的转诊**：将被拒绝或退回的转诊排除在计算之外，会掩盖数字化工具往往正是为了减少的返工负担。
- **报告均值而非中位数和百分位数**：少数耗时极长、被退回的转诊会将均值大幅拉高，远超典型患者的实际体验。
- **将周转时间与总等待时间混淆**：周转时间仅涵盖分诊环节；患者的整体体验还包括后续的临床候诊名单，那是一个受不同容量限制约束的独立指标。
- **不区分各子阶段**：仅测量端到端时间的服务，无法判断缓慢的数字是由转诊方提交信息不完整、接诊服务方的分诊产能，还是二者共同造成的。
